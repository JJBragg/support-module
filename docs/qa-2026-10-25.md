# QA pass, phases 1 to 5

Run on 2026-10-25 against the staging instance, by hand and by script, as
three different people: not logged in, Artur (agent), Monika (admin).

Everything below was exercised on
<https://support-module.staging.oregon.platform-os.com>. Nothing was tested
on production, and production does not exist yet.

## Short version

Seven defects found, seven fixed and verified the same day. One of them was
a whole feature that had never worked. One was an authorization rule that
was enforced in one place and open in another.

No data loss, no way in for anyone who should not be in, and no cross
tenant leak. The parts that carry the most risk, the inbound webhook, the
department scoping and the write endpoints, all held.

## What was tested

### Inbound email, 11 cases

| Case | Expected | Result |
| --- | --- | --- |
| Correct secret in the path | 200, ticket created | pass |
| Secret as `?token=` instead | 200, same behaviour | pass |
| Wrong secret | 403, nothing written | pass |
| No secret at all | 403 | pass |
| No sender address | 422, nothing written | pass |
| Reply with `In-Reply-To` | threads onto the ticket | pass |
| Reply with only `[#9]` in the subject | threads onto the ticket | pass |
| Reply to a closed ticket | reopens to Under Review | pass |
| Subject starting URGENT | opens at P0, not P1 | pass |
| Recipient matching no department | falls back, does not drop the mail | pass |
| Attachment metadata | filename and type kept, file not stored | pass |

Quoted history is split off the body and hidden behind a disclosure.

### Ticket list, 14 cases

Views (mine, unassigned, all open), status filter, department filter,
priority tabs, group by priority, group by status, search, top three per
group, See all, collapse a group, bulk assign, bulk unassign, reorder with
the arrows. All pass, two with fixes below.

Counts are consistent: the sidebar status counts add up to the All open
total, and each group header matches the rows under it.

### Ticket detail and composer, 10 cases

Header position and previous/next, status change, assignee change,
department change, priority change, private note, @mention, reply, reply
with send-and-set-status, empty body refused for both note and reply.
All pass.

A reply builds real threading headers and is recorded as undelivered,
because no provider is connected. That is the honest state, not a defect.

### Settings, 12 cases

Department edit and save, duplicate department name refused, status
reorder, status rename, status type change, status type change refused on
the two statuses that carry a job, status add, duplicate status name
refused, agent role change both directions, department access toggle both
directions, provider test send, secret reveal. All pass.

### Access control, 13 cases

| Who | What | Result |
| --- | --- | --- |
| Not logged in | every page and every POST endpoint | sent to log in, nothing written |
| Agent | the queue, a ticket, notes, status changes | allowed |
| Agent | `/support/settings` and every settings POST | 403 |
| Agent | drag reorder, and the move endpoint posted by hand | not offered, then 403 |
| Agent with no departments | the queue | empty, 403 on any ticket |
| Admin | everything | allowed |

The settings link is not rendered for an agent, and neither are the drag
handles or the reorder arrows.

### Robustness, 8 cases

- Cross site request forgery: a POST without the token is rejected. Checked
  by posting from a logged in session with the token removed, then
  confirming nothing changed.
- Open redirect: `return_to` set to `https://evil.example/x`,
  `//evil.example/x`, `javascript:alert(1)` and `\\evil.example` all land
  back on the queue. A real path is honoured.
- Cross site scripting: an email whose subject and body carry
  `<img src=x onerror=...>` and `<script>` renders escaped everywhere, in
  the list and on the detail page. The only script tag in the document is
  the module's own.
- Unknown ticket number and a non numeric one both return a real 404.
- Every one of the 209 translation keys the templates ask for exists.

## Fixed during this pass

**1. The search box had never matched anything.** The haystack column
`c__search` was written on every ticket and was not in the query's result
selection, so the Liquid that filters on it compared against an empty
string. Every search returned nothing. Now searching by subject, by contact
address and by ticket number all work.

**2. An agent could change the work order.** Reranking is Admin only, and
that was enforced on drag and drop and on the move endpoint. It was not
enforced on the priority buttons, which move a ticket to the top of its new
group, which is the same thing. A translated string for the locked state
already existed and had never been wired to anything, so this was an
unfinished guard rather than a decision. The buttons are now disabled for
an agent with the reason shown, and the endpoint refuses the post as well,
so sending the form by hand does not get around it.

**3. Quoted text claimed a count it did not have.** The first message in a
ticket showed "Show quoted text, 0 earlier messages". The customer had
quoted something; it just predates the ticket. It now reads "Show quoted
text".

**4. The 403 page told agents the wrong thing.** An agent who opened a
settings page was told their account has no access to the support queue and
to ask an Admin to add them as an agent. They are an agent. It now says the
screen is Admins only.

**5. An anonymous POST to a ticket endpoint could tell you whether a ticket
existed.** The page looked the ticket up before checking the permission, so
a missing ticket bounced to the queue and a real one bounced to the login
page. Small, but it is an oracle. The unscoped check now runs first, and
the department scoped one still runs once there is a ticket to scope it to.

**6. Typing `#12` in the search box found nothing** although the box says
"Search ticket #, subject or email". The hash is now stripped.

**7.** Two from earlier the same day, before this pass: the private note
button rendered near black on dark brown because an element reset outranked
every class rule in the stylesheet, and the status name field collapsed to
four characters on rows carrying a badge.

## Open, and not defects

- **Priority is now Admin only.** That follows the rule as written. If
  agents should be able to escalate a P1 to a P0 without being able to
  reshuffle a group, that is a different design and worth deciding: the
  honest version is that the escalation lands at the bottom of the new
  group rather than the top.
- **Departments and statuses cannot be deleted.** Deleting a status with
  tickets on it needs a reassignment screen.
- **Attachments keep the name and lose the file**, pending the platform
  question with the engineers.
- **Replies do not reach anyone** until SendGrid is connected.

## Not tested, and why

- **Responsive and phone layout.** Phase 6, not built.
- **Real email delivery, inbound or outbound.** No provider, no MX record.
- **The @mention email actually arriving.** platformOS accepts it and skips
  the send because this instance has no `test_email` set in the Partner
  Portal.
- **The superadmin break glass path**, where a host superadmin with no
  agent record counts as an Admin. Verifying it means removing an agent
  record from a live account.
- **The last admin guard**, which refuses to demote the only Admin. There
  are three Admins on staging, so it cannot fire without first removing
  two.
- **Scoping across two departments.** Only one exists, so scoping was
  tested by taking every department away from an agent instead.
- **The 500 ticket cap on the queue and the ticket number race**, both
  known and both needing volume to show.

## Test data left on staging

QA created tickets 9 to 13, one of them with a deliberately nasty subject
full of angle brackets, and a status called QA Holding. Everything else was
put back the way it was: priorities restored, bulk assignment reverted,
Artur's department access and role restored, status order restored.

The leftovers can be removed on request. Nothing in the module deletes
tickets, so it would be a direct record delete.
